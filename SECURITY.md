# Security policy — GoreeCloud Database

**Development preview. Do not deploy on an Internet-facing host.** No production SLA, audit or vulnerability-response guarantee is established.

- Report suspected vulnerabilities privately using GitHub's private vulnerability-reporting feature if enabled, rather than publishing exploit steps or secrets.
- Generated `.env` must remain local and uncommitted. `scripts/init_env.py` never prints secrets and refuses to overwrite them.
- Database, API and REST services are isolated on a private data network; only the nginx gateway is published on localhost. The unauthenticated `/api/readyz` endpoint checks private SELECT-only database connectivity and exposes status only; never expose the development gateway on public ingress. REST is available via /rest/ on that gateway. External access requires a separately evaluated, identity-aware TLS proxy.
- Backend authorization uses independent shared admin/viewer bearer tokens. [OIDC RS256 verification](docs/OIDC_READER.md) still grants **global reader only** for existing catalog and object APIs, after strict issuer/audience/scope/signature/expiry checks. Only an additional explicit `goreecloud.database.write` claim permits [owner-isolated personal notes INSERT](docs/PERSONAL_RLS.md) under PostgreSQL RLS, never administrator writes or platform-wide tenant isolation. Reads use a separate SELECT-only role. Rotate shared and OIDC credentials using their respective approved processes.
- Use a non-superuser `gc_api` for the management API. SQL identifiers are allowlisted and quoted; values are parameterized.
- Android refuses plaintext HTTP. No persistence of administrator tokens is implemented.
- Bounded CSV page export reads through `gc_reader`, escapes spreadsheet formula prefixes in headers and cells and uses 2 MiB response limits. This is **not** a per-user privacy export; shared viewer credentials read all exposed `app` tables.
- This service does not yet offer certified disaster recovery, **platform-wide** RLS tenant separation, actor-attributed/tamper-evident audit, distributed/identity-scoped rate limiting, or multi-factor identity. The isolated `gc_personal.notes` RLS demonstration is not a production tenant boundary for the general `app` and `gc_storage` schemas. The preview's administrator write endpoints have only a [single-process 30-per-minute throttle](docs/WRITE_THROTTLE.md); this is not production anti-abuse protection. Read-only tokens can read the entire exposed `app` schema; never interpret them as per-user scopes. Catalog SSE notifications are metadata-only and lossy; authorization is a shared preview token, not tenant-scoped. The small-object API stores up to 1 MiB per file with a 512-object / 128 MiB global database quota, but all viewer tokens can download all objects. No per-user ACL, virus scanning, owner-scoped quotas or retention controls exist.
